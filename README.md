# Love Me Peach — AR-тамагочи

2D-персонаж, который «живёт» на реальном столе через камеру телефона, а вы за ним ухаживаете.
Kotlin, классические View (без Compose), ARCore для трекинга, OpenGL ES 2.0 для отрисовки.

## Как играть

1. При первом запуске выберите, о ком заботиться: **Мира** или **Кай**.
2. Наведите камеру на стол, дождитесь сетки и тапните по ней — персонаж встанет на стол. Тап по другому месту стола переставляет его.
3. Ухаживайте: **Покормить**, **Подарок** (не чаще раза в 20 минут), **Поговорить**, тап по персонажу — погладить. Он пульсирует, над головой вылетают сердечки.
4. Шкалы: **сытость** и **настроение** падают со временем, даже когда приложение закрыто. Если персонаж голоден или грустит, **симпатия** понемногу уходит.
5. Стадии по симпатии: Знакомство → Друзья → Симпатия → Влюблённость → Вы пара. На финале игра предложит остаться или начать заново.
6. Кнопка **Сброс** в любой момент стирает прогресс и возвращает к выбору персонажа.

Прогресс сохраняется на телефоне (SharedPreferences). Темп и значения — в `CareState.kt`, реплики — там же в `Phrases`.

## Что нужно

- **Android Studio** 2026 года выпуска (нужна поддержка Android Gradle Plugin 9.0).
- **Телефон с поддержкой ARCore**, Android 7.0 или новее. Список моделей: <https://developers.google.com/ar/devices>.
  На телефоне должны стоять «Сервисы Google Play для AR»; если их нет, приложение само предложит установить.
- USB-кабель и интернет на компьютере (при первой сборке скачиваются Gradle и библиотеки).

## Сборка и запуск

1. Распакуйте архив.
2. Android Studio: **File → Open** и выберите папку `ArTamagotchi` (ту, где лежит `settings.gradle.kts`).
3. Дождитесь окончания синхронизации Gradle (полоска внизу окна). Если Studio предложит установить SDK Platform 36 или принять лицензии — соглашайтесь. Предложение обновить Gradle-плагин можно принять или отложить.
4. Включите на телефоне отладку: **Настройки → О телефоне** → семь раз нажмите на «Номер сборки» → **Для разработчиков → Отладка по USB**.
5. Подключите телефон кабелем и подтвердите на нём запрос об отладке.
6. Выберите телефон в списке устройств на верхней панели и нажмите **Run ▶** (Shift+F10).
7. Разрешите доступ к камере. Наведите телефон на стол и медленно поводите им — появится сетка. Дальше тапайте.

Сборка из командной строки: `./gradlew assembleDebug` (в Windows — `gradlew.bat assembleDebug`). Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

Трекинг лучше работает при хорошем свете и на поверхности с рисунком. Однотонный глянцевый белый стол ARCore видит плохо — положите на него журнал или салфетку.

## Как получить готовый APK

Один файл `.apk` получается только сборкой проекта: для неё нужны Android SDK и библиотеки с серверов Google. Есть два пути.

**Через GitHub, без Android Studio.** В проекте лежит готовый сценарий сборки `.github/workflows/build-apk.yml`.

1. Создайте на GitHub пустой репозиторий.
2. Загрузите в него содержимое папки `ArTamagotchi` — так, чтобы `settings.gradle.kts` оказался в корне репозитория. Папка `.github` тоже должна попасть внутрь.
3. Откройте вкладку **Actions**: сборка «Build APK» запустится сама и займёт несколько минут.
4. Готовый файл появится в разделе **Releases** под именем `ArTamagotchi.apk` (прямая ссылка, можно открыть с телефона). Запасное место — вкладка Actions → последний запуск → **Artifacts**.

Если сборка завершилась с красным крестиком, откройте её и посмотрите шаг «Build debug APK» — там будет текст ошибки.

**Через Android Studio.** Откройте проект, как описано выше, и выберите в меню **Build → Generate App Bundles or APKs → Generate APKs** (в старых версиях — Build → Build APK(s)). Файл появится в `app/build/outputs/apk/debug/app-debug.apk`.

**Установка.** Скопируйте APK на телефон, откройте его и разрешите установку из этого источника. Это отладочная сборка: у сборок с разных компьютеров разные подписи, поэтому перед установкой новой версии старую иногда приходится удалить.

## Как подставить своего персонажа

1. Подготовьте **PNG с прозрачным фоном**.
   - Ноги персонажа должны касаться нижнего края картинки. Именно нижний край ставится на стол, и пустая полоса снизу заставит персонажа «парить».
   - Пустые поля по бокам тоже лучше обрезать: тап засчитывается по всему прямоугольнику картинки.
   - Размер — любой до 2048 пикселей по большей стороне.
2. Назовите файл `character_female.png` или `character_male.png` — смотря кого заменяете. В именах ресурсов Android допустимы только строчные латинские буквы, цифры и `_`.
3. Положите его в `app/src/main/res/drawable-nodpi/`, заменив файл, который там лежит.
   В Android Studio: слева вверху переключите вид с **Android** на **Project**, раскройте путь до папки `drawable-nodpi` и вставьте файл (Ctrl+V). Или просто скопируйте файл в эту папку через Проводник.
   Папка именно `drawable-nodpi`: из неё Android берёт картинку как есть, не растягивая под плотность экрана.
4. Запустите приложение заново (Run ▶).

Имя, рост на столе и картинку каждого персонажа задаёт `enum Gender` в `CareState.kt`.

Рисуете пиксель-арт — поставьте `PIXEL_ART = true` в `ArRenderer.kt`, иначе пиксели размажутся.

Оба персонажа оригинальные, нарисованы специально для этого проекта, с ними можно делать что угодно. Векторные исходники лежат в `art/`: откройте в Inkscape, чтобы перекрасить волосы или одежду, и экспортируйте в PNG. Мягкий свет по краю силуэта в готовом PNG добавлен уже после экспорта, в самом SVG его нет.

## Что подкрутить

| Что | Где | Сейчас |
|---|---|---|
| Высота персонажа на столе | `SpriteCharacter.kt` → `heightMeters` | `0.18f` (18 см) |
| Гладкая картинка или пиксель-арт | `ArRenderer.kt` → `PIXEL_ART` | `false` — сглаживание; для пиксель-арта поставьте `true` |
| Как спрайт поворачивается к камере | `SpriteCharacter.kt` → `billboardMode` | `UPRIGHT` — стоит вертикально, как картонная фигурка; `FACE_CAMERA` — всегда параллелен экрану |
| Сила и длительность пульсации | `SpriteCharacter.kt` → константы `PULSE_…` | до 18%, 0.8 с |
| Прятать сетку после установки персонажа | `ArRenderer.kt` → `HIDE_GRID_WHEN_PLACED` | `true` |
| Размер ячейки сетки | `PlaneRenderer.kt` → `CELL_SIZE_METERS` | 5 см |
| Сколько сердечек за тап | `HeartParticles.kt` → параметр `count` в `emit()` | 6 |
| Тексты подсказок | `res/values/strings.xml` | — |

Ширина персонажа считается сама из пропорций картинки.

## Как это устроено

Каждый кадр `ArRenderer.onDrawFrame()` делает одно и то же:

1. `session.update()` — ARCore отдаёт свежий кадр камеры и положение телефона в комнате.
2. Кадр камеры рисуется на весь экран как фон.
3. Обрабатываются тапы. Если луч из точки тапа попал в прямоугольник спрайта — персонажа «гладят». Иначе `frame.hitTest()` ищет точку на столе, и в ней создаётся **якорь** (Anchor).
4. Рисуется сетка плоскостей.
5. Рисуются тень, спрайт и сердечки.

**Почему спрайт не улетает.** Якорь — это точка, которую ARCore удерживает на реальной поверхности. Каждый кадр мы берём его координаты в мире и матрицы камеры (вид и проекция). Телефон сдвинулся — изменились матрицы, и та же точка мира попала в другое место экрана.

**Билборд.** Прямоугольник спрайта строится из трёх осей. В режиме `UPRIGHT` «вверх» — это вертикаль мира, «вперёд» — направление на камеру по горизонтали, «вправо» — их векторное произведение. В режиме `FACE_CAMERA` оси берутся прямо из матрицы вида, и спрайт получается параллельным экрану. Оси, размер и положение складываются в матрицу модели (`SpriteCharacter.buildModelMatrix()`).

**Сглаживание.** Картинка загружается с мипмапами (уменьшенными копиями), поэтому издалека края не рябят. Подробности — в `GlUtil.createTexture()`.

**Прозрачность.** Android загружает PNG с «предумноженной» альфой, поэтому смешивание включено как `GL_ONE, GL_ONE_MINUS_SRC_ALPHA`. Тест глубины выключен: в сцене только плоские картинки, и они рисуются в нужном порядке.

## Если что-то пошло не так

**Gradle не синхронизируется, ошибка про несовместимую версию Android Gradle Plugin.**
Android Studio старше, чем нужно для AGP 9.0. Обновите её (Help → Check for Updates).

**Синхронизация падает по другой причине, связанной с версиями.** Надёжный обходной путь — дать Studio самой создать проект под её версии, а потом перенести в него код:

1. **File → New → New Project → Empty Views Activity**. Language: Kotlin, Minimum SDK: API 24, Package name: `com.example.artamagotchi`.
2. Скопируйте из этого архива поверх созданного проекта:
   - все `.kt` из `app/src/main/java/com/example/artamagotchi/` (с заменой `MainActivity.kt`);
   - папку `app/src/main/res/` (с заменой файлов);
   - `app/src/main/AndroidManifest.xml`.
3. Удалите в новом проекте папку `res/values-night`, если она есть.
4. В `app/build.gradle.kts` в блок `dependencies` добавьте строку
   `implementation("com.google.ar:core:1.54.0")`
   и нажмите **Sync Now**.

**«Это устройство не поддерживает ARCore».** Телефона нет в списке по ссылке выше, или на нём нет сервисов Google.

**Эмулятор.** ARCore в эмуляторе работает только на образах с Google Play и с виртуальной комнатой вместо камеры. Проверять удобнее на настоящем телефоне.

**Чёрный экран или вылет.** Откройте вкладку **Logcat** внизу Android Studio. При вылете причина будет в красном тексте с пометкой `FATAL EXCEPTION` (туда же попадает текст ошибки шейдера, если он не скомпилировался). Ошибки отдельных кадров и AR-сессии ищите по словам `ArRenderer` и `MainActivity`.

**Сетка не появляется.** Больше света, поверхность с рисунком, телефон двигать плавно из стороны в сторону, а не вращать на месте.

## Что проверено, а что нет

Проект писался без Android SDK под рукой, поэтому:

- **Проверено:** весь Kotlin-код проходит проверку типов компилятором Kotlin — но против вручную написанных заглушек Android и ARCore API, а не настоящих библиотек. Математика билборда, попадания тапа в спрайт, тени, пульсации и частиц прогнана числовым тестом в пяти сценариях (разные положения камеры, оба режима билборда): спрайт не зеркалится, не переворачивается, ноги стоят в точке якоря, тап засчитывается только внутри спрайта. XML-файлы корректны.
- **Не проверено:** настоящая сборка через Gradle и запуск на телефоне. Сценарий сборки на GitHub тоже ни разу не запускался. Шейдеры не компилировались реальным видеодрайвером. Если при первой сборке всплывёт ошибка — скорее всего, она будет про версии в Gradle-файлах или про сигнатуру какого-то метода API.

Версии в проекте: Android Gradle Plugin 9.0.1, Gradle 9.1.0, compileSdk 36, ARCore 1.54.0. Взяты не самые последние, а те, что поддерживает любая Android Studio 2026 года. Самая свежая ARCore на момент написания — 1.57.0; начиная с 1.56 библиотека нацелена на API 37, так что при её обновлении, возможно, придётся поднять `compileSdk` и версию Gradle-плагина.

## Что делать дальше

- **Покадровая анимация.** Соберите кадры в одну картинку (спрайт-лист) и передавайте в шейдер `QuadRenderer` смещение и масштаб текстурных координат — получится моргание, ходьба, эмоции.
- **Сам тамагочи.** Состояния (голод, настроение, сон) с таймерами, кнопки «покормить» и «поиграть» обычными View поверх камеры, сохранение в `SharedPreferences`.
- **Точный тап.** В `SpriteCharacter.hitTest()` уже считаются координаты попадания внутри картинки — можно проверять по ним альфу пикселя и не засчитывать тапы по прозрачным местам.
- **Плавная анимация.** Сейчас кадры идут с частотой камеры (около 30 в секунду). `config.setUpdateMode(Config.UpdateMode.LATEST_CAMERA_IMAGE)` в `MainActivity` отвяжет отрисовку от камеры.
- **Перекрытие реальными предметами.** Depth API в ARCore позволяет прятать спрайт за чашкой или рукой.
- **Память между запусками.** Якорь живёт только в пределах одной сессии. Чтобы персонаж оставался на том же месте после перезапуска, нужны Cloud Anchors — либо просто просите поставить его заново.
